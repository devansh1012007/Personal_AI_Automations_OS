## 1. Goal and strategy

**North star.** A looping OS: one local-first runtime where agentic loops of any kind (chat, coding, research, self-improvement) are installable, selectable, recoverable components; where the durable asset is the **chain of trust** — what ran, what passed, who approved — and where "dark factory" style continuous agent work is possible *because* every effect is owned, gated, and attested.

**The lead, corrected per strategy.** Crash recovery is table stakes already built and drilled; it is not the story. The story the substrate earns is **evidence, replay, and attestation**: the ledger's value is that a third party can verify *what actually happened* without trusting the producer. Every wave below is chosen to externalize that value:

- **W4** makes it *feelable* (a chat with real memory — the demo that proves the substrate to a human).
- **W7** makes it *showable to others* (attested PRs, flight-recorder sidecar, cross-harness evals, the control plane).
- **W6/W8** make it *extensible without dilution* (loops as governed components, not forked internals).

**Moat bets** (event-sourcing alone is copyable; these are the defensible layers):

| Bet | Meaning here | Concrete carrier |
|---|---|---|
| Standard | The bundle/verify format and the pipeline protocol as de-facto specs others can implement | W7 attested-bundle spec doc + `paa verify` on a clean machine; W6–W8 protocol doc frozen at `paa-pipeline/1` after the rule of three |
| Distribution | Installability into existing harnesses rather than a new silo | W4 MCP server (PAA memory/tools inside Claude Code/Codex/Cursor/OpenCode); W7 `paa record` sidecar + GitHub Action; `uv tool install paa` |
| Data | The owner's own eval corpus and memory as compounding data no vendor has | W7 eval harness runs on this repository; memory grows with real use from W4 onward |

**Determinism rule ("logic, not LLM").** Every gate in this plan — smoke, policy, eval scoring, rollback decisions, watchdog escalation triggers — is deterministic code. A model may propose; it never decides a gate. This is already the house rule ([../README.md](../README.md) "Models propose; deterministic policy decides"); waves W7–W9 lean on it for error-catching without model judgment.

**Local-first control plane.** One coding thread across Claude Code, Codex, Cursor, and OpenCode: PAA holds the thread (mandate, context, memory, ledger); harnesses are hands that come and go. Delivered progressively: W4 (harnesses reach PAA memory via MCP) → W7 (`paa record`/`paa thread`: harnesses run *inside* PAA's evidence boundary, threads survive harness swaps).

**Anti-scope (not built in this plan):** no web dashboard, no cloud/hosted service, no LLM-based gatekeeping, no container runtime as default backend, no multi-user accounts, no marketplace economy/payments, no fine-tuning. All parked in W9+ or [../VISION.md](../VISION.md) conditional horizons.

### 3.2 The UI specification — `paa chat`, production grade

**Framework.** Textual (async-first, rich-based, MIT). The existing Rich operator dashboard is untouched; chat is a new app in `src/paa/tui/chat/` with a `--plain` fallback so the product never hard-requires the extra.

**Design language.**

- Palette, semantic and few: `bg` = terminal default (never force black), `surface` for rails and tables; **memory/cognition = cyan**, **trust/ledger = amber**, **policy/denial = red (denials and failures only)**, **session/isolation = violet**, **success = green**. All meaning is text + glyph first (e.g., denial shows the rule name), color second — color-blind safe and high-contrast-theme compatible via Textual theme variables, no hardcoded hex for semantics.
- Layout grammar: one header bar (1 row), body, two-row footer (input + keybinding hints). No boxes-in-boxes; 1 px rules only; whitespace does the separating.
- Motion: none except the streaming caret; respects reduced-motion. Density: comfortable default, `/compact` mode for power users.

**Screens.**

1. **Chat** (default) —

```
┌ paa chat ─ session s-02b1 · isolated · model:local-echo · policy:STANDARD ┐
│ user:      what did I tell you about the deploy schedule?                 │
│ assistant: You said deploys freeze on Fridays — added as a fact on        │
│            2026-11-19 (confidence 0.82, cited 3×).                        │
│ ┄ system: recalled 4 facts · consulted 12 · budget 2.3k/8k ┄ (dim)        │
│───────────────────────────────────────────┬ MEMORY (Ctrl+T) ─────────────│
│                                            │ consulted                    │
│                                            │  ▸ deploy-freeze-fri  0.82  │
│                                            │  ▸ rust-toolchain     0.64  │
│                                            │ captured this turn          │
│                                            │  ▸ "prefers async" → signal │
│───────────────────────────────────────────┴──────────────────────────────│
│ ❯ _                                                                       │
└ ^T rail · ^P palette · ^L ledger · ^K policy · /sessions · /memory · Esc⏹┘
```

   Message stream is a virtualized list (10k turns, no jank); assistant output renders markdown; streaming appends with a 30 ms throttle and a stop affordance (Esc). The **memory rail** (toggle, Ctrl+T) shows the context bundle's provenance: facts consulted (confidence, age, times-cited), signals captured this turn, token budget gauge — memory made *visible*, which is the product's entire point. System lines (recalls, tool denials, journal notes) render dim and one-line.
2. **Sessions** (`/sessions`) — session cards with isolation badges, first/last turn, fact counts; actions: switch, fork (branch from a turn id), resume, archive; fork shows a diff preview of the memory scope.
3. **Memory** (`/memory` or Ctrl+M) — the memory dashboard: KPI strip (facts, hot/cold, signals/day, contradictions, quarantine), sortable fact table (confidence, last-served, provenance), fact detail modal with **lineage** (the ledger chain: which signals/episodes produced and touched it), the signal funnel (signals → validated → facts → hot), curator state (next decay sweep, budget).
4. **Ledger** (Ctrl+L) — the event chain for the current session, filters by kind/actor; chain-verification badge (cheap local hash-chain check on load); `paa ledger` remains the deep view.
5. **Policy** (Ctrl+K) — grants in effect for this session (from the mandate), pending clearances (approve/deny inline for gate-class actions), denial log with the rule that fired.

**Command surface.** Palette (Ctrl+P) fuzzy over all actions; slash set: `/new /sessions /memory /ledger /policy /context` (show the assembled packet verbatim — trust-through-observability) `/compact /fork /export /model /doctor /quit`. Keybindings are rebindable in config; full keyboard operability is a gate, not a nicety.

**Error taxonomy (microcopy rule: what happened + why + next action).** `ModelError` (retryable: timeout/rate-limit → inline retry with backoff and circuit breaker after 3; permanent: config → doctor hint), `PolicyDenial` (names the rule and how to request clearance), `StorageError`, `SessionError`. No raw tracebacks in-app; F12 opens a log drawer with the structured events; everything also lands in the rotated log file.

**Production-grade checklist (the definition for this wave):**

- Startup: < 2 s cold (lazy model/LLM imports — pattern already proven in `cli/main.py`), < 500 ms warm resume; measured, asserted in CI perf smoke.
- Crash-safety: input drafts journaled (debounced 250 ms); session state autosaves on unmount and SIGINT; `paa chat --resume <id>` always works — resume is already the substrate's native trick, the UI must not become the one place it fails.
- Offline-first: `echo` model path means the whole product (chat, memory, MCP server) demos with zero network; no telemetry, ever.
- Accessibility: complete keyboard control; visible focus; high-contrast theme; screen-reader announcements on turn completion (not per token); no color-only signification; CJK-safe rendering (Textual).
- Security: MCP server loopback + token; secrets never enter the ledger (existing redaction + canary test pattern); policy on by default; tool-free MVP means the attack surface is memory writes only.
- Packaging: `uv tool install "paa[tui]"`; `paa doctor` covers chat/MCP; versioned config schema.
- Testing: Textual `Pilot` component tests; one fake-model e2e per screen; input fuzz (unicode, CJK, ANSI injection) on the renderer.

**Performance budgets:** context assembly p95 < 250 ms (the gatherer is already bounded); first-token render < 100 ms after model response; 60 fps scroll at 10k turns; memory rail update < 50 ms per turn.

## 9. Cross-cutting rules (all waves)

1. **Status discipline:** every plan carries a `Status:` line and every wave's closing commit flips the plan's status, the ROADMAP/VISION rows it satisfies, and the README block — in the same commit as the gate report. The two stale-line incidents that misled the October audit are the reason this is a rule, not a habit.
2. **Determinism rule:** no gate is ever model-decided (§1).
3. **Ledger-before-effect:** holds for every new surface — chat turns, MCP tool calls, recorder observations, attested bundles. No new event type ships without `v=1` payload goldens + replay property coverage (ADR-0046 pattern).
4. **Security defaults:** loopback + token for every listening surface; secrets only via the proxy; redaction + canary tests extend to each new surface in the same wave, not later.
5. **Testing standard:** every wave's gate = ruff 0, mypy ≤ baseline (3, Windows-only — re-verify per wave), full suite green, conventions + `scripts/status.py --check` green, and the wave's own acceptance tests. Chaos/kill coverage is mandatory for anything that claims resumability.
6. **Estimates are solo-maintainer** and ordering aids, as the house scale says.

# SPEC: Make PAA do real work, with its authority recorded

*Written 2026-11-09 against `main` @ `b8570a6` · Implements ROADMAP Horizon 1 (narrowed;
see [D-1](#5-decisions-made-in-this-spec)) plus repository hygiene · Intended to be
executed by waves of parallel tasks with per-task reports under
`docs/operations/<date>-next-spec/`*

---

## 1. Why this, why now

PAA's spine is built and heavily tested, but it has never done real work for a real
person. Three facts on `main` make that concrete:

1. **There is no filesystem or shell tool.** The coder agent drives the *runtime*, not
   a working tree (`docs/coder-agent.md`, "Known limitations"; the coding-specialist
   pilot says the same). `paa agent` cannot change a project.
2. **The coder loop is not in the ledger.** Its turns live in session transcripts, so
   it gets neither crash recovery nor hash-chained history.
3. **Tasks do not record who requested them or under which policy.** There is no
   mandate concept in `src/`.

Everything on the roadmap after this (external agents, attested changes, evidence for
reviewers) assumes PAA can change a project and record doing so. This spec closes that
gap and nothing else. **If time is short, protect Waves 1 and 2 and cut everything
marked *stretch*.**

## 3. Objective and success demo

**Objective.** `paa agent` can read, edit, test, and commit in a real working tree
under permission control; every step and the authority behind it are in the ledger;
a hard crash does not lose or repeat work.

**Success demo (S1).** On `examples/fixtures/buggy_calc/` (one failing test):

1. `paa agent --workspace <fixture>` with a frontier provider and the prompt
   *"fix the failing test"*.
2. The agent reads files, edits one, runs the tests through the sandbox, and commits.
   Each mutating call prompts in ASK mode.
3. `paa ledger <session>` shows a mandate at the head, then proposed / completed
   events for every call, each with a hash and the sandbox isolation level.
4. Repeat, sending `kill -9` to the process at a random tool call. Restart with
   `--resume`. The final tree is correct, no committed side effect ran twice, and any
   call whose outcome could not be determined was reported to the model, not retried.

S1 passing is the exit criterion. A *model* that fails the task is a valid, recorded
result (see N3.1); a *harness* that loses or repeats work is not.

## 5. Decisions made in this spec

Proposed defaults, so implementers do not stall. Veto any of them before Wave 1 starts.

| ID | Decision | Rationale |
|---|---|---|
| D-1 | **H1.4 is narrowed to `MANDATE_GRANTED` / `MANDATE_REFUSED`.** `TRIGGER_RECEIVED` and `ELIGIBILITY_DECIDED` wait for a real event source. | Nothing produces triggers yet; designing the schema without a producer repeats the "abstract before three cases" mistake. |
| D-2 | **Work tools live in `paa.coder`**, not as marketplace skills. | Fewest moving parts; reuses the permission policy and hooks. Revisit when third parties need to add tools. |
| D-3 | **Edits go through `validation.patch.PatchApplier`**; `bash` goes through `Sandbox.run`. | Reuses the journalled, hash-verified, rollback-capable machinery instead of a second write path. |
| D-4 | **Policy version = SHA-256 of the canonicalised effective policy config**, plus a human label. | Content-addressed, cannot drift silently. Resolves ROADMAP decision #2. |
| D-5 | **Requester identity is asserted, not authenticated, in v0**, and recorded with `identity_assurance: "asserted"`. | Loopback single-user today. Pretending otherwise would be a false claim of authority. |
| D-6 | **A mutating call whose outcome is unknown after a crash is never auto-repeated.** The model is told and decides. | Repeating `git commit`, `bash` or a network call is worse than asking. |
| D-7 | **Git tools exclude push, force, config, and hook changes.** | Smallest useful surface; irreversible remote effects are out of scope. |
| D-8 | **Runtime-level default mandate has basis `implicit` and is counted as such.** A setting `policy.require_explicit_mandate` (default `false`, forced `true` in LOCKDOWN) refuses it. | Avoids rewriting thousands of tests while keeping the coverage metric honest. |
| D-9 | **Move `VISION.md` into `docs/`** and fix `docs/README.md`. | The README, ROADMAP and research note already assume it there. |

**Required tests for Wave 1.**

- **Path jail (property test, Hypothesis).** Generated paths including `..`, absolute
  paths, Windows drive letters and UNC prefixes, mixed separators, and symlinks never
  resolve outside the workspace. Explicit symlink-escape test.
- **Protected paths** (`.git/` internals, `.env*`, the PAA home directory): reads and
  writes denied, with a ledger-visible denial reason.
- **Encoding and newlines.** UTF-8 round trip, CRLF preserved on edit, BOM handled,
  binary files refused by `read_file` and `grep` with a clear message.
- **Edit semantics.** Zero matches and multiple matches fail without changing the
  file; a successful edit returns a patch SHA that matches `compute_patch_sha256`.
- **Limits.** Oversized reads and outputs are truncated and marked, never silently.
- **Shell.** Timeout kills the process tree; output cap holds; the isolation level is
  reported on every call; environment is allowlisted (no ambient secrets).
- **Git.** `git_commit` in a repo with no staged changes fails cleanly; no tool can
  reach a remote.
- **Permissions.** Each tool is correct in PLAN (mutating refused), ASK (prompt for
  mutating only), and LOCKDOWN modes.

## 7. Interfaces

### Tool surface

| Tool | Mutating | ASK default | Notes |
|---|---|---|---|
| `read_file`, `glob`, `grep` | no | allow | Path-jailed; size-capped; protected paths denied |
| `git_status`, `git_diff` | no | allow | Read-only |
| `write_file`, `edit_file`, `apply_patch` | yes | prompt | Through `PatchApplier`; returns patch SHA |
| `bash` | yes | prompt | Through the sandbox; reports isolation level |
| `git_add`, `git_commit` | yes | prompt | Fixed argv; no remote operations |

### Event payloads (v1, abbreviated)

```json
// MANDATE_GRANTED
{ "v": 1,
  "requester": {"kind": "cli", "id": "devansh@host"},
  "identity_assurance": "asserted",
  "basis": "explicit",
  "policy_version": {"sha256": "…", "label": "local-ask"},
  "scope": {"workspace": "…", "permission_mode": "ask", "budget": {"tokens": 200000}} }

// TOOL_CALL_PROPOSED   (written before any side effect)
{ "v": 1, "call_id": "…", "tool": "edit_file",
  "args_sha256": "…", "args_preview": "path=calc.py …",   // redacted
  "isolation_level": "SUBPROCESS_JAIL" }

// TOOL_CALL_COMPLETED
{ "v": 1, "call_id": "…", "ok": true, "duration_ms": 41,
  "result": {"sha256": "…", "size": 212, "preview": "…", "blob": null},
  "effect": {"kind": "file_edit", "patch_sha256": "…", "path": "calc.py"} }

// TOOL_CALL_FAILED
{ "v": 1, "call_id": "…", "reason": "interrupted",
  "state": "applied | not_applied | unknown" }
```

Correlation: one coder session is one correlation id. `session_id` carries the CLI
session. `causation_id` of each outcome is its `PROPOSED` event.

## 9. Risks specific to this work

| Risk | Mitigation |
|---|---|
| Path escape through symlinks, drive letters, or case-insensitive filesystems | Property test and explicit cases (Wave 1); resolve before comparing; deny on doubt |
| New event types break replay or recovery | N2.1 property test over all orderings before any producer ships |
| Coder events inflate the ledger | Blob large outputs; log hashes and previews only |
| `PROPOSED` written but process dies before execution | Classified as `not_applied`; safe to repeat for edits; `unknown` only for shell and git |
| Layering: `coder` importing runtime internals | `ToolJournal` protocol in `loop.py`; implementation in `journal.py` |
| A weak local model makes S1 look like a harness failure | S1 uses a frontier provider; separate harness faults from model faults in the report |
| Mandate default (D-8) hides missing authority | Coverage metric counts `implicit` separately; strict mode exists and is tested |
| Scope creep into ACP, sources, or panels | Section 4 is the boundary; changes need a new spec |

## 10. Timebox and stop rule

Waves 0–3 are roughly 2–3 weeks of solo work; treat that as an ordering aid, not a
commitment. **If Wave 1 is not done after 7 days, cut `glob`, `grep`, and the git
tools and ship `read_file`, `edit_file`, `bash`** so that S1 is still possible. Do
not start a new wave while the previous wave's tests are red.

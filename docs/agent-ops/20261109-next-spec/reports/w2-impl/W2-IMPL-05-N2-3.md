## 3. Root cause
Two missing pieces, not one: (a) the sweep cannot see coder lineages as anything but resumable tasks because `_NO_PHASE_CHANGE` makes their events phase-inert while their head stays `is_terminal = 0` — the exact failure ADR-0046 flagged as open; (b) nothing closes a PROPOSED-without-outcome, so a kill between PROPOSED and COMPLETED leaves the ledger claiming a call that is neither executed nor refused, and the model on `--resume` is told nothing. The persisted intent (N2.2) makes classification decidable, but only the resume side can name the target file: the ledger's PROPOSED payload carries hashes, never the path (shape-summary preview, N2.2 §4), so ledger-only file classification would have to guess. That is root-cause scope, not a detail to paper over.

## 4. Approach chosen and why (alternatives rejected)
**Sweep closes, report classifies, resume refines.** Three decisions carry the design, each forced by an ADR freeze:

1. **The FAILED row stays golden-exact; the classification travels in the report + note, not a new `state` field.** ADR-0046 rule 4 forbids new fields inside `v=1` without a version bump, and the N2.1 golden pins FAILED at 8 fields. The spec/plan sketches assumed a `state` field, but implementing the sketch verbatim would break the frozen contract. So `close_interrupted_calls` writes `reason="interrupted"` plus the PROPOSED row's `args_sha256`/`isolation_level` — nothing else — and `InterruptionState` rides on `CorrelationRecovery.interrupted` and into the resume note. Rejected: the sketch's literal `state` field (contract violation) and classifying nowhere (fails the mission).

2. **Sweep-time file edits are `UNKNOWN`; resume-time verdicts are precise.** The ledger holds hashes, never the path (N2.2's shape summaries), so a ledger-only `applied` would require scanning the tree for a hash match — a heuristic that cannot distinguish "my file applied" from "some other file happens to hash equal". The journal's own docstring forbids guessing here, and so does this code: `classify_interrupted(..., live_checked=False)` is `UNKNOWN` for everything. At resume time the transcript's `TOOL_CALL` turns name the path, the live file is hashed through the jail, and the same pure function produces the exact verdict. `live_checked` is the parameter that keeps the two sites from silently agreeing on a guess. Rejected: manifest-scan classification (ambiguous, O(tree) per call) and closing only at resume (the sweep would leave PROPOSED open forever on coder homes whose sessions never resume).

3. **Exemption is a sweep branch, not a replay change.** `_is_coder_only_lineage` (all non-neutral types in the ADR-0046 audit set, with `RECOVERY_REPLAY_COMPLETED` neutral so a pre-N2.3 sweep row can't flip a coder lineage back to "task") returns `SKIPPED_CODER_LINEAGE` before any reconcile/requeue/audit write; mixed lineages close their interrupted calls and then follow the ordinary task path. The mandate types are in the set because `cli/coder.py` leaves one `MANDATE_GRANTED` on its own lineage per run — equally not resumable task work. Rejected: exempting by correlation-id prefix (no such prefix exists; `new_correlation_id()` is a bare UUID) and doing the close inside `_record_sweep` (sweep-audit semantics are already subtle; the close deserves its own visible step).

**Resume join by `(tool, args_sha256)`.** The transcript records pre-hook args; the ledger attests post-hook args. A redacted call therefore fails to match and reads `UNKNOWN` — the safe direction, and the only direction that never invents a verdict. Repeated identical calls match FIFO off a per-key queue, so the Nth identical call classifies by the Nth matching turn. Rejected: joining by `call_id` (the transcript never records it), joining by position (a resorted transcript would mis-assign verdicts).

## 8. Long-run test (Source/Load/Hostile/Operability/Reversal)
- **Source:** ADR-0046 v1 contracts + the store's dedupe. The sweep writes only what they declare; `test_sweep_closes_proposed_without_outcome` is the tripwire (exact-dict equality, so adding a `state` field inside v1 would fail it loudly, as intended).
- **Load (100x, concurrency, partial failure):** one extra ledger read per open lineage at boot + one dedupe-then-seal append per interrupted call (zero appends when none — the common case). No caches, no unbounded state (`find_interrupted_calls_for_session` is bounded by `limit=10_000`). Crash *during* the sweep: a half-closed lineage re-sweeps and closes the rest — the closes are idempotent by discriminator, so the kill-drill's "loses/repeats nothing" holds for the sweep itself (pinned by the double-sweep test + the kill test's second sweep).
- **Hostile input:** malformed PROPOSED payloads (missing/wrong-typed ids) are skipped, never raised — a hostile row cannot stop the sweep closing well-formed neighbors; a `session_id` carrying `:` cannot reach the discriminator (the journal rejects on write; the sweep's find keys on payload text only). The resume join never follows a `..`: the target is jailed before hashing, and any jail/OSError failure degrades to `UNKNOWN` (never a false `applied`). A file that grew huge is hashed whole for the live check — the same bounded-blast shape as the journal's pre-hash (disclosed pre-existing exposure, not new here; see §14).
- **Operability:** observe via `CorrelationRecovery.interrupted` / `RecoveryReport.interrupted_count` and `paa ledger` (FAILED `reason=interrupted` rows name the call). Roll back by reverting the code commit before the first sweep over a coder home; after that, ADR-0046 one-way door applies. No config flag (the sweep is the path); no migration.
- **Reversal:** executed mutation probe in §7; exemption/closure reversals fail by count assertions (see §7).

## 9. Edge cases and abuse scenarios
DENIED-alone (hook-block) is never interrupted (no PROPOSED exists — construction, plus pinned). PROPOSED+DENIED (permission/ASK deny after proposing) is resolved, not interrupted. A call with malformed `tool` (empty) is still closed (shutting the door beats leaving it open); a PROPOSED with a *malformed hash* (e.g. `"not-a-hash"`) flows into `classify_interrupted` and lands on `UNKNOWN` by mismatch — never `APPLIED`. A resumed session with a hook-redacted call fails the transcript join and reads `UNKNOWN`. A resume against a ledger whose interrupted calls predate this code closes them too (the scan is by session id, not by version — forward recovery of pre-N2.3 crashes works). Double `--resume` without a new crash closes nothing new and injects no duplicate note (outcome check + content-idempotent note). A mixed lineage that is parked on a human gate or over the retry ceiling still closes its coder calls (audit rows) before the park/abandon branch — the gate logic itself is untouched.

## 10. Performance and security
Performance: boot-time only; per open lineage one `read_correlation` (derivable work, no new substrate), per interrupted call one append. The resume scan is `events_since(limit=10_000)` — bounded, newest-first not required because session ids are unique. No per-tool-call cost is added anywhere (the loop/journal path is untouched).
Security: the close attests nothing new about args (copies `args_sha256` + actual `isolation_level` from PROPOSED); no content, no preview, no path enters any ledger row (the transcript join stays in-memory and the note carries tool/call-id/classification only — no file bytes, no raw paths beyond the tool's own name). The sweep module gains no `coder` import (layering: `ledger` must not depend on `coder`), so the fresh-interpreter sweep half of the conventions lock still passes.

## 12. Deviations from plan/brief
1. **No `state` field on the FAILED row** (plan:41 + spec:224-226 sketch). ADR-0046 (the frozen contract this brief orders read) pins FAILED at 8 fields and forbids new fields inside `v=1` (rule 4). The classification travels in `CorrelationRecovery.interrupted` + the resume note; the ledger row carries exactly `reason="interrupted"`. Evidence-driven resolution, not a shortcut: implementing the sketch verbatim would break the golden contract the ADR calls the tripwire.
2. **Vocabulary: `not_applied`, not `pending`.** The brief says "applied/pending/unknown"; the plan (N2.3 row, §H T-N2-5, §I) and spec (§7) all say `not_applied`. Implemented under the plan/spec name; the docstring records the mapping (`pending` == `NOT_APPLIED`).
3. **Sweep-time file edits classify `UNKNOWN`.** The plan says "file edits by comparing file hash to persisted pre/post SHA". The ledger carries no target path (N2.2 shape-summary preview), so the sweep cannot obtain a live hash without guessing at the file. The precise verdict is produced at resume with the transcript's path; the sweep reports and closes. Root-cause scope, disclosed in code (§4.2) — flagged for the wave reviewer rather than hidden.
4. **`CODER_SESSION_STARTED`/`ENDED` still unemitted** (carried from N2.2 §12.5). Neither is required for the exemption (it keys on `TOOL_CALL_*`/`MANDATE_*` rows the journal already writes) or for the resume scan (keyed by payload `session_id`), so emitting them here would be scope expansion.

## 14. Known limitations, risks, rollback notes
- Sweep-time `UNKNOWN` for file edits (§4.2) means a pure-sweep kill drill reports `unknown` where the resume flow refines to the exact verdict; T-N2-5's "resume produces correct classification" is the acceptance the tests pin.
- `find_interrupted_calls_for_session` is `limit=10_000`-bounded (oldest-first by sequence): a home with >10k tool-call events could strand an old interrupted call past the bound. Local-first homes are far below this; the bound is surfaced by paging callers if ever hit.
- The resume transcript join is exact-or-`UNKNOWN`: a hook-redacted `write_file` (args changed post-transcript) reads `UNKNOWN` even though the ledger holds pre/post. Safe direction; only a journal-side path field (out of write-set, ADR-versioned) closes it fully.
- Live-file hashing reads the whole target file at resume time (same shape as the journal's pre-hash — disclosed pre-existing exposure, W2-REV-02 R2-MINOR-4; a hostile multi-GB prior's cost is bounded by the write tools' own prior-read caps on the tool path, not on this read).
- Rollback: `git revert` of the code commit before the first sweep/resume over a coder home; after that, ADR-0046 one-way door (pre-N2.1 binaries raise on read).

## 15. Where I am least confident
The sweep-time `UNKNOWN` boundary (§4.2): it is the honest consequence of "ledger holds hashes, never paths", but a reviewer may want the sweep to scan the workspace for a `post`-matching file after all. I rejected that as a guess, and the resume path delivers the exact verdict — but the per-call `applied` rate for a sweep-only (never-resumed) session stays at `UNKNOWN` forever, which is a real operability cost worth the reviewer's eyes.

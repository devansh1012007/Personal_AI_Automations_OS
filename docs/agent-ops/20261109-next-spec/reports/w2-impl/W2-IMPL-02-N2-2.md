## 3. Root cause
N2.1 froze the vocabulary and protocol but shipped no producer: nothing translated a tool call into ledger rows, so (a) the ledger attested nothing about redacted args (the PRE hook's work left no trace), (b) no persisted intent existed for N2.3 to classify a crash, and (c) the composition root failed fast on any journal value. Root cause is the missing producer + missing journal point in the loop's gate order, not a defect in the existing permission/hook logic, which is preserved verbatim when no journal is configured.

## 4. Approach chosen and why (alternatives rejected)
**Journal module owns payload construction and intent.** `LedgerToolJournal(ledger, correlation_id)` builds each payload from an explicit field list (so a future field addition cannot smuggle `fact_id` past the `_assert_no_fact_id` tripwire — MINOR-2 producer half) and appends via `LedgerEvent.create(..., attempt=0, discriminator=…)`, letting the store's own dedupe do the work. Rejected: a journal-side dedupe cache (second dedupe = drift vs the store's transaction) and pydantic payload models (no other ledger event is modelled, ADR-0046 rejected them).

**Loop builds the ctx, journal module computes intent.** The loop stays tool-agnostic: `_build_journal_ctx` computes `args_sha256` (canonical JSON, the one serialisation the ledger hashes with), the preview, isolation, and minted call_id, while `compute_persisted_intent(workspace, tool, args)` lives in journal.py because classifying file-tool crashes is the journal's job. Rejected: intent computed inside `run()` and reported upward (needs a second protocol method; the ADR froze three). The accepted fidelity limit is disclosed in the function docstring: `post` is predicted under the tools' text model (UTF-8, LF-normalised, BOM re-attached), exact for LF files; a CRLF prior the applier re-joins differently degrades to N2.3 `unknown` (never auto-repeat), never to a false `applied`.

**Preview renders shapes, never content.** First implementation rendered short string values verbatim after `redact()`. W2-IMPL-04's canary test proved an opaque secret (no `sk-` shape, never handed to `redact` as a literal) survives that in a free-form `command` arg. Env-collection of known secrets would not fix it either (the test's canary is not in the process env). `args_preview_redacted` now renders every string as `<str len=N sha256=xxxxxxxx>` and containers recursively, with secret-named keys as `***`. This is the only rule that holds against unknown secrets by construction; the attested `args_sha256` already provides exact identity, so nothing is lost. (The final blanket `redact()` pass was removed in the same commit: it mangled the `api_key=***` mask into `***REDACTED***` via the `api-key=` pattern — a self-inflicted readability bug caught by both test suites.)

**Loop mints an empty legacy call_id; journal rejects empty/colon ids.** `ToolCtx` allows `call_id=""` for hybrid callers, but an empty id collapses every call to one discriminator (unjournalled execution). The loop mints `uuid4().hex` per call when empty, so journalled loop calls always carry a real id; direct journal callers with empty/`:`-bearing ids get `ValueError` before any append, and the protocol's raise-to-abort means the tool does not execute. Rejected: silently journaling with a derived id inside the journal (hides a caller bug; the mint point should be one, in the loop).

**Agent journals by default.** `CoderAgent.build(journal=None)` now constructs `LedgerToolJournal(runtime.ledger, correlation_id or new_correlation_id())` and passes `workspace` through to the loop. Rejected: journal-only-when-passed (the mission is that the coder loop is in the ledger; a default-off wire would leave the CLI unjournalled until N2.4). All 115 coder tests (loop/agent/integration/runtime_tools) pass with the default on, so no existing caller depended on unjournalled execution.

**Isolation discovery via declared shapes only.** `_isolation_for` checks a tool's `isolation_level` attribute, then a no-arg `preflight()` mapping (the shell tool's shape), then `NONE` (in-process tools). Rejected: reaching into `BashTool._sandbox` (private access that would attest a guess if the backend changed) and attesting a loop-wide configured level (requested, not actual — exactly what ADR-0046 forbids).

## 8. Long-run test (Source/Load/Hostile/Operability/Reversal)
- **Source:** ADR-0046 v1 contracts + the store's dedupe are the source; the journal writes only what they declare (exact-dict tests are the tripwire). Persisted intent is computed from jailed file bytes at PROPOSED time, which is what makes N2.3 classification decidable.
- **Load (100x, concurrency, partial failure):** 2 appends per tool call, each a single dedupe-then-seal transaction (the store's `_chain_tip` + savepoint path, unchanged). No caches, queues or unbounded state added; preview/intent work is O(args) + one file read for file tools (bounded by the write tools' own size caps on the predicted side; the pre-hash reads the prior file — a hostile multi-GB prior would be read whole by `_hash_file`; see S14). Partial failure: crash between PROPOSED and outcome leaves exactly the PROPOSED row N2.3 looks for; duplicate delivery dedupes by key.
- **Hostile input:** `:`/empty ids rejected pre-append (collision pair pinned); escaped paths yield null intent, never a raise, and never a hash of an outside file (jail-then-hash via `workspace.root / Path(raw)` exactly like the tools); hostile `fact_id` in a future payload edit trips `_assert_no_fact_id` at append; oversized preview capped; binary/non-UTF-8/missing prior → null prediction, never a guess.
- **Operability:** observe via `ledger.read_correlation` (rows carry tool, isolation actual, intent, redacted preview); roll back by reverting the commit before the first journal write to a shared home (N2.1 one-way-door note); no migration, no config flag (the journal is the path, not a feature toggle).
- **Reversal:** mutation probe in S7 (validation disabled → 2 failures for the right reason); by code path, moving PROPOSED before the PRE hook fails the redaction-order test, removing COMPLETED's result-hash requirement fails the `ValueError` test, and reverting the runtime import fails `test_get_type_hints_resolves_tool_ctx` with the original `NameError`.

## 9. Edge cases and abuse scenarios
Hook block → DENIED without PROPOSED (DENIED is proof of non-execution; no PROPOSED exists to classify — covered by construction, not by a dedicated test: the block path shares the ctx build with the normal path). Unknown tool → no journal rows (no dispatch, no intent to classify; session transcript still records the error). Journal refusal (bad ids) → raise, tool never executes (fail-closed; a test could pin the raise-through-loop, currently pinned at journal level). Tool returning a JSON error value (not raising) → COMPLETED (execution happened; the string is the result the model reasons about). POST hook observes after COMPLETED is journalled (the tool's side effect is already attested; the formatter cannot unwrite a row). `after(ctx, True, None)` raises rather than writing a success row with nothing hashed. Repeated identical calls in one step: distinct minted ids → distinct rows.

## 10. Performance and security
Performance: negligible vs model latency; one `preflight()` dict per sandbox-tool call via `_isolation_for`; one file read per file-tool call for the pre-hash. Security: the ledger attests post-hook args only (B-7 closed by ordering + test); the preview cannot disclose content (shape summaries, secret-key masks); journal refusal aborts execution (no unjournalled side effect); isolation attested is the backend's actual level via its own `preflight()`, never a requested level; jail-then-hash prevents intent hashing outside the workspace; `fact_id` tripwire prevents tier-state fabrication from any future payload edit. No secrets, tokens or env values written to code, tests, reports or commits (test canaries are the documented opaque/fake values in the sibling suite).

## 14. Known limitations, risks, rollback notes
- `_hash_file` reads the whole prior file for the pre-hash; a hostile multi-GB prior in the workspace would be read into memory. Bounded in practice by the write tools' own `MAX_CONTENT_BYTES` prior-read gate (the tool refuses over-limit priors; intent hashing reads before that refusal, so the journal would read what the tool then refuses). A stat-size pre-check mirroring `_read_prior_text` is the obvious hardening and was not added to avoid duplicating the tool's limit logic across the boundary — flagged, not fixed.
- `post` fidelity for CRLF priors degrades to `unknown` (S4/S8).
- Hook-blocked calls produce DENIED without a preceding PROPOSED; N2.3 must treat DENIED-alone as proof of non-execution, not as an interrupted call.
- Rollback: `git revert` of the code commit before the first journal write to a shared `PAA_HOME`; after that, the ADR-0046 one-way door applies (pre-N2.1 binaries raise on read).

## 15. Where I am least confident
The CRLF `post`-hash fidelity (S4): the prediction mirrors the tools' text model but cannot mirror the applier's line-ending re-join from the args alone, so an LF-exact prediction can still read as `unknown` for CRLF files. This is safe (never auto-repeats) but means N2.3's `applied` rate for CRLF edits is lower than it could be; only a tool-reported intent (a second protocol method) closes it fully.

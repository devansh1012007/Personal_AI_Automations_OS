## 4. Approach chosen and why (alternatives rejected)

Default sandbox `SubprocessSandbox(SandboxSettings(max_capture_bytes=64KB))` + tool-level combined 64KB truncation with flag. JSON error-as-value + JSON result with `exit_code/timed_out/isolation_level/network_severed/truncated`. `preflight()` + `build_shell_tools()` factory for N1.5. Rejected: always-refuse subprocess+allow_network=False (would make tool unusable on Windows dev host without Docker); silent run claiming nothing (dishonest); editing sandbox/agent/`__init__` (out of WRITE-SET).

## 8. Long-run test (Source/Load/Hostile/Operability/Reversal)
- Source: `Sandbox.run` + `build_child_env` reused; no second exec path, no `shell=True`, no `os.environ` read for PATH/env.
- Load (100x, concurrency, partial failure): `SubprocessSandbox` is per-run stateless (`sandbox/base.py:606-611`); tool holds no per-run state; per-call cap bounds transcript growth; timeout bounds hang (600 max). Partial failure (killed mid-run) still yields a `SandboxResult` (total outcome), not an exception.
- Hostile input: empty/oversized/NUL/control command, env key injection (`=`, NUL, leading digit, 65+ entries, 8193-char values), timeout 0/negative/huge/NaN/bool/string-garbage, non-bool network flags, unknown args — all validated before `SandboxSpec`; `WorkspaceViolation`/`SandboxError`/`ValueError` converted to JSON values, never swallowed.
- Operability: result JSON carries `isolation_level`/`network_severed`/`backend`/`duration_ms`/`memory_enforcement` for the Wave-2 ledger; logs carry verdict only (no command/env/stdout); `preflight()` answers before exec.
- Reversal: revert `shell_tools.py` → `tests/coder/test_shell_tools.py` fails on import (`ModuleNotFoundError` for `paa.coder.shell_tools`); revert `_truncate_combined` → cap test fails; revert env allowlist → canary test fails; revert `network_severed` reporting to `True` → isolation/preflight tests fail.

## 9. Edge cases and abuse scenarios
pwsh/bash binary missing → JSON `ok False` "failed to start sandboxed process" with `PROCESS` reported (proven here by `test_missing_shell_reports_start_failure`). Command writing outside cwd is PROCESS-limit (filesystem not confined; `preflight filesystem_confined False` documents it; absolute-path reads are not blocked by a cwd jail). NUL/control in command/env rejected; env whole-splat tripwire (`SandboxSpec._reject_ambient_env_smell`) untouched (our `_MAX_ENV_ENTRIES=64` plus pattern keeps the tool far from the tripwire unless the model deliberately passes 40+ vars with SYSTEMROOT+USERPROFILE, in which case `SandboxSpec` refuses and we return the error as JSON). `allow_network=True` explicitly reports `network_severed=False` even where severance would have been possible. `SandboxSpec` env-splat construction failure surfaced as JSON, not as a crash. Concurrent calls independent (no shared mutable state). `run()` catches only `WorkspaceViolation`/`SandboxError`/`ValueError` around spec+run; unexpected backend bugs propagate to the loop's handler rather than being swallowed.

## 10. Performance and security
Timeout 600 max bounds hang; 64KB combined cap bounds transcript/ledger bloat; env allowlist prevents ambient secret leak (canary probe proves at tool layer, see §11 probe); child `PATH` is the sandbox bootstrap (no host toolchain leak); `build_child_env` `PATH` never widened (brief §6); command capped at 100k chars; env capped at 64 entries × 8192 chars. No new dependency, no network, no fixed ports, no Docker.

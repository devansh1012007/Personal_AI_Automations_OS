## 3. Root cause
**MAJOR-1 (single-file grep).** `_walk`'s contract was implicitly "walk a directory tree". `os.walk` (and any readdir walk) has no entry for a file root, so grep's file-shaped input fell through the enumeration with zero candidates and the tool reported success-with-nothing. The schema lied because the implementation never handled the file shape. The fix belongs at the shape boundary: grep knows its `root` may be a file or a directory, so it must pick the candidate set accordingly, rather than assuming `os.walk(root)` enumerates one file.

**MAJOR-2 (walk cap).** `_walk` swallowed its own budget signal: the early `return` at the cap is invisible to a `for`-loop caller (a generator's `return` value rides `StopIteration.value`, which `for` discards). Two call sites therefore folded only their *own* limits into `truncated`, and the walk's partial enumeration was presented as complete. The root cause is a lost signal across a generator boundary, not two missing `if`s: any fix that re-checks the cap in each caller, or that makes `_walk` raise, would duplicate or change the walk's contract. The signal must be threaded out of `_walk` explicitly.

**MINOR-2 (uncounted skips).** The grep loop's skip taxonomy had three incrementing sites (escape, protected, `OSError`) and two non-incrementing ones (binary, non-UTF-8). Binary/non-UTF-8 were deliberately *skipped* (correct search semantics) but never *counted*, breaking the `scanned + skipped` reconciliation. Two missed increments — a 2-line scope.

## 4. Approach chosen and why (alternatives rejected)
### 4.1 Single-file grep: branch in `_Grep.run` (chosen) vs in `_walk`
Chosen: `if root.is_file(): candidates = iter([(single_rel, root)]) else: candidates = _walk(...)`, with `single_rel` the workspace-relative POSIX spelling of the jailed root. Rejected: putting the file branch inside `_walk`. The brief phrases the fix as "if jailed root is_file(), search that one file", and `_walk` has exactly two callers — glob (always the workspace-root directory) and grep. A file branch in `_walk` would give `_walk` an ambiguous contract (`_walk(file)` without `root_is_workspace` has no workspace ancestor to spell a relative name against), while grep already holds the workspace root. Keeping `_walk` dir-only preserves its "never follow, enumerate a tree" contract and puts the shape decision where the shape is known. The single-file candidate still flows through the *same* per-entry loop (glob-filter, re-jail via `assert_inside_workspace`, protect check, capped read, binary skip, line matches), so a symlink or protected file cannot bypass any check the directory walk performs. `root` is already jailed+protected before `is_file()` is called, so a direct single-file path to `.env` still denies with the frozen reason (probe-verified, §9).

### 4.2 Walk cap: one-element `list[bool]` out-param + shared note helper (chosen)
Chosen: `_walk(..., cap_hit: list[bool] | None = None)`; both cap sites set `cap_hit[0] = True`; glob/grep pass `[False]`, then fold `walk_hit` into `truncated` (`truncated or walk_hit`) and compose `note` via `_truncation_note(limit_hit, limit_text, walk_hit)`. The helper is the single source for the walk phrase `f"walk capped at {_MAX_WALK_ENTRIES} entries; results are incomplete"`, so glob and grep cannot drift. The interpolated cap number is truthful under the tests' stubbed cap (says `2`), not hard-coded `10000`. Alternatives rejected:
- *Generator `return` value / `StopIteration.value`:* invisible to the existing `for rel, entry in _walk(...)` loops; using it would require manual `next()` plumbing at both call sites — more code, same effect, and it changes how the loops read.
- *Eager list return `tuple[list, bool]`:* would materialise up to 10k entries even when glob/grep break after 7/5 matches, wasting the walk they never needed; the lazy generator with an out-param preserves the early-exit behaviour.
- *Duplicate note logic inline at both call sites:* ~7 duplicated lines per site and two copies of the walk phrase to keep in sync — rejected by the helper (the review itself flagged duplicated private helpers as not worth it, but the *wording* duplication is correctness-bearing, so one source is justified here).
- * raising from `_walk` on cap:* would turn a bounded enumeration in the common case into an error value and force callers to catch; the walk succeeded partially, it is not a refusal.
The out-param approach keeps `_walk` backward compatible (default `None`), preserves laziness, and is documented on `_walk` with the `StopIteration` rationale so a future caller does not re-lose the signal.

### 4.3 Binary/non-UTF-8 skips: count them (taken, 2 lines)
Chose to take MINOR-2: `files_skipped += 1` in both skip branches. It is 2 lines, testable in 8 lines, and `files_skipped` has no other consumer than the model-facing JSON (verified by repo-wide grep: only `fs_read_tools.py` emits it; no sibling imports the payload shape). Deferring would have left the `scanned + skipped` undercount in place. No existing test asserts `files_skipped` for these paths, so the additive count breaks nothing.

## 14. Known limitations, risks, rollback notes

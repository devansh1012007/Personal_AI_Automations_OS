## 4. FINDINGs — the nine patterns audited against the gate's own verdict

Every case below was put through the **policy agent itself** (the same
`handle()` path the SAFE refusal uses), not through a regex in isolation.
Reproduction script: `/tmp/w2impr04-8908/audit_patterns.py`.

### F-1 (MAJOR) — the "unqualified delete" rule's answer depends on the *position* of the step in the plan

`\bDELETE\s+FROM\s+\w+\s*(;|$)` requires the statement to be terminated by a
semicolon **or to be the last thing in the rendered plan**. The renderer
joins the plan's parts with newlines, and the pattern is anchored on `;` or
end-of-**string**, so a delete that is not the last step is invisible:

```
  DELETE FROM users as the ONLY step         -> STATUS_BLOCKED  (irreversible operation under SAFE mode: unqualified delete)
  DELETE FROM users followed by another step -> STATUS_APPROVED  ()
  DELETE FROM users; followed by another step-> STATUS_BLOCKED  (irreversible operation under SAFE mode: unqualified delete)
```

**The same command is refused or allowed depending on what follows it in
the plan.** A security rule whose answer depends on the plan's shape is not
a security rule.

*Candidate patch:* `\bDELETE\s+FROM\s+[\w.]+\b(?!\s+WHERE)` — the table name
may be schema-qualified, and the rule is about the **absence of a WHERE
clause** rather than about a terminator.

*Why I did not apply it:* that patch matches the phrase "delete from the
old notes" in a **goal** or a step description, because the gate scans
prose as well as commands; a plan whose goal merely mentions "delete from
the staging area" would be blocked under SAFE and would take the risk score
to 0.8 in every other mode. The current pattern's false negatives and the
candidate's false positives are both real, and picking between them is a
**policy decision** (what should SAFE refuse?) that belongs in its own
task, not in a coverage fix.

### F-2 (MAJOR) — `git push -f` is not refused

`\bgit\s+push\s+.*--force\b` requires the long option; the short one is the
same operation.

```
  ALLOWED  git push -f (short force flag)   ['git', 'push', '-f', 'origin', 'main']
```

*Candidate patch:* add `-f` — but **not** as `.*-f\b`, which is the naive
form and which false-positives on a chained command:

```
  git push -f origin main              naive True  narrow True
  git push origin main -f              naive True  narrow True
  git push origin main && ls -f        naive True  narrow False   <-- 'ls -f' is not a force push
  git push --follow-tags origin main   naive False narrow False
```

The narrow form (`\bgit\s+push\b(?=[^;&|]*\s-f\b)` — the option must belong
to the git push command itself) is the correct one, and it is a *different
rule shape* from the nine in the table. It needs its own pattern and its
own case, i.e. a change to the gate's rule set rather than a patch to a
rule.

### F-3 (MINOR) — the `rm` rule misses the flag spellings a real `rm` accepts

`\brm\s+-[rRf]{1,2}\b` does not match `-rfv` (the `\b` after the flag class
fails against the trailing `v`) and knows nothing of the long options:

```
  ALLOWED  rm -rfv (verbose flag)                     ['rm', '-rfv', '/data']
  ALLOWED  rm --recursive --force (long options)      ['rm', '--recursive', '--force', '/data']
  ALLOWED  rm --preserve-root -rf (option before the flag)  ['rm', '--preserve-root', '-rf', '/']
```

The long-option family needs a scan across the command line rather than an
adjacency rule, which is a different rule shape again — and a scan across a
command line is exactly where a false positive ("rm" in prose, "rm" in a
path) starts to cost.

### F-4 (MINOR) — the SQL rules miss spellings that a planner emits

```
  ALLOWED  DELETE FROM public.users (schema-qualified)   ['psql', '-c', 'DELETE FROM public.users;']
  ALLOWED  DELETE FROM "users" (quoted identifier)       ['psql', '-c', 'DELETE FROM "users";']
  ALLOWED  TRUNCATE events (no TABLE keyword)            ['psql', '-c', 'TRUNCATE events;']
```

`\w+` stops at the `.` in `public.users` and at the `"` in `"users"`;
`\bTRUNCATE\s+TABLE\b` requires the `TABLE` keyword, which PostgreSQL does
not. The schema-qualified delete is a one-character fix
(`\w+` → `[\w."]+`); the `TRUNCATE` one is not, because `\bTRUNCATE\b`
alone would match the English word "truncate" in a goal.

### F-5 (MINOR) — the deletion rules are anchored on `os.`, and the table is not exhaustive of irreversible operations

```
  ALLOWED  os.removedirs (removes a tree)          ['python', '-c', "import os; os.removedirs('/data/d')"]
  ALLOWED  pathlib Path.unlink (not os.unlink)     ['python', '-c', "from pathlib import Path; Path('/data/x').unlink()"]
  ALLOWED  git clean -fd (deletes untracked files) ['git', 'clean', '-fd']
  ALLOWED  git checkout . (discards local edits)   ['git', 'checkout', '.']
  ALLOWED  DROP MATERIALIZED VIEW (stored rows)    ['psql', '-c', 'DROP MATERIALIZED VIEW daily_totals']
```

The ROADMAP's phrase *"SAFE blocks deletion"* is true of the nine rules and
of nothing else: the table is a list of nine, not a list of every way to
destroy data. That is not a defect in the nine — it is a **scope statement
that the ROADMAP's phrasing does not make**, and the honest form of the
claim is *"SAFE blocks these nine irreversible operations"*.

### 4.1 What I recommend, and what I did not do

All five are **reported, not fixed**. Each fix is one line of regex and a
behaviour change to a security gate whose input includes prose; each trade
is a false negative traded for a false positive; and the ADR that would
record the new rule shape is in `docs/**`, which my brief forbids. The
recommended next task is a **dedicated one**: "the policy gate's rule set",
with a corpus of real command spellings to adjudicate the trade-offs
against, rather than a regex patch smuggled into a coverage fix.

### 5.1 (MINOR) — `policy.py::_check_lockdown`'s egress branch is **unreachable dead code**

`src/paa/agents/policy.py:216-220`:

```python
for step in steps:
    perms = set(step.get("required_permissions", []))
    if {Permission.NET_EGRESS.value, Permission.EXTERNAL_WRITE.value} & perms:
        return PolicyVerdict.blocked("egress/external-write requested under LOCKDOWN")
```

`LOCKDOWN` grants only `SANDBOX_RUN` (`core/types.py:265`), and
`_check_permissions` runs **first** (`policy.py:143-146`), so a step that
declares an egress permission is already refused:

```
  a step declaring PERM_NET_EGRESS under LOCKDOWN -> STATUS_BLOCKED
  reason: "permissions not granted in LOCKDOWN: ['PERM_NET_EGRESS']"
```

The gate's *behaviour* is right (the plan is refused either way); its
*message* is unreachable, and the branch is a second guard that can never
fire. Deleting the whole branch leaves the suite green (mutation M4).
**Recommendation:** either delete the branch or move the check ahead of
`_check_permissions` — the second is a behaviour change (a different
message, and a different order of refusals) and needs its own task.

### 5.2 (MINOR) — the traversal guard only sees **quoted** paths

`_check_paths` finds candidates with
`re.findall(r"[\"']([^\"']*(?:/|\\\\)[^\"']*)[\"']", blob)`, so the
traversal branch fires for a *string* command (`cp 'x' '../../other/…'`)
but not for the **argv** form (`["cp", "x", "../../other/…"]`), which the
renderer space-joins without quotes. The argv form is how a plan carries a
command. The test added in §2.4 exercises the branch as it is written
(a quoted path); the gap is reported here.

### 5.3 (NIT) — `AGENTS.md`'s "mypy 0 errors across `src/` and `tests/`" is true of `src/` and not of `tests/`

`MYPYPATH=src mypy src` → **0 errors, 137 files** (the gate, green).
`MYPYPATH=src mypy tests` → **195 errors in 38 files**. Without
`MYPYPATH=src`, mypy cannot resolve the editable install at all, so
`paa` becomes `Any` and the error set changes shape (17 errors in
`tests/agents` alone, most of them "Class cannot subclass Agent (has type
Any)"). The *enforced* gate in `AGENTS.md` is `mypy src`, which is green;
the claim about `tests/` is not, and it is not true of the tests tree
today. Not mine to fix; recorded so that the next agent does not read the
tests tree as clean.

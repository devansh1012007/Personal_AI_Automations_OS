## 2. Code changes (per file, with rationale; root-cause level, no band-aids)

### 2.1 `deploy/fetch-images.sh`

**The root cause of R-W1-101 and R-W1-102 was one thing: the reader detected the
*spelling of a line* rather than the *presence of a construct*.** The fix is therefore
one change, not two: the reader now parses a line into a **key** and a **value**, and
acts on the key.

* `normalise_key()` — the key as YAML reads it: the spaces around it and the quotes
  around it are not part of the name. Compose reads `image :` and `"image":` as the
  key `image` (`[RAN]`, §0), so the reader does too.
* The top level, the `services:` map and a service's own map are each read by their
  key. `include:` is refused on the key — block, flow and scalar forms alike — and
  the YAML merge key `<<:` is refused on the key, at every level that can inject keys
  into a map the reader reads.
* An **alias** is refused wherever it appears under `services:` (the merge key is an
  alias in a third place; an alias on a key the reader does not read is still a
  reference it cannot resolve).
* The `image:`/`extends:`/`build:`/`profiles:` rules became one rule that dispatches
  on the key, so a key spelled with a space before the colon or in quotes is read
  the way Compose reads it. **A missed `image:` is a service dropped from the plan,
  silently** — the same failure as the merge key, with the same fix.

**R-W1-103 was an ordering problem, and it is now an ordering fix.** The profile names
travel on the **row** (`action<TAB>image<TAB>service<TAB>profiles`); the reader no
longer decides a service's membership. `build_plan` runs the invariants (the digest
pin, the variable reference, the empty `image:`) over **every** row, and only then
decides what the *fetch* does with a service whose profile is not enabled. The
exclusion is a property of the *fetch*, made after the rules have run.

**`COMPOSE_PROFILES` is honoured** — Compose's own variable, read by `docker compose
up` too, so the plan and the stack agree. A profile the operator enabled is a profile
whose images are fetched; a profile that is not enabled is reported as not fetched, in
the report *and* on stderr, and named in the final message.

**The `profiles:` list is read** (block form and flow form, with the items quoted or
not, with a comment or a blank line inside the block), because the list decides which
services the deployment runs. A `profiles:` that is not a list at all is refused —
Compose refuses such a file itself (`services.gpu.profiles must be a array`).

### 2.2 The three shapes the review did not reach (§0, last three rows)

While auditing the fix I compared the script's plan with `docker compose config` over
a corpus of 24 shapes, and found three more shapes of the same class — **silent**,
exit 0, a plan missing a service:

| Shape | Compose | The script, before | Now |
|---|---|---|---|
| a service written as a flow mapping — `postgres: {image: …}` | **accepts** | ignored → the service is missing from the plan, exit **0** | **refused** (`the service postgres is written as a flow mapping`) |
| a `services:` map written as a flow mapping — `services: {…}` | **accepts** (and merges with another file's `services:`) | ignored → the service is missing from the plan, exit **0** | **refused** (`the services map is written as a flow mapping`) |
| a service whose keys are not at four spaces | **accepts** | the `image:` was invisible → the service was missing from the plan, exit **0** | **refused** (`the service postgres has keys this reader does not understand`) |

The rule they share is now written down once, in the script and in the ADR: **the line
between a refusal and an ignorance.** A shape **Compose refuses itself** (a service
written as a plain scalar, a `profiles:` that is not a list, an `image:` that is not a
string) cannot be deployed, so the reader's answer about it does not matter. A shape
**Compose accepts** and the reader does not implement is a hazard, and it is refused.

The third one needed a portable way to ask "is this line indented deeper than four
spaces": an interval expression (`{5,}`) is **not** portable — mawk 1.3.4 does not
backtrack into one, so `/^ {5,}[^[:space:]#]/` silently fails to match a six-space
line `[RAN]`. The reader **counts** the indent instead, which is exact and is what
the Python reader does.

## 4. Optimizations applied and evidence of benefit (and ones declined, with reason)

* **One refusal set, drawn along one line.** The ten refused shapes are not ten
  independent rules; they are one rule ("a construct Compose accepts and the reader
  does not implement is refused") applied to ten constructs, and the *reason* each
  one is refused is now the same sentence. That is what makes the set maintainable:
  the next shape is not a new rule but a new entry in a list.
* **The key is read once.** The reader parses a line into a key and a value in one
  place (`normalise_key` + `index(line, ":")`), and every rule dispatches on the key.
  Before, each rule re-derived the key with its own prefix match, which is how the
  `image :` hole happened: four rules, four spellings, four chances to be wrong.
* **The profile list is read once, in the reader.** The shell never parses YAML: it
  receives a comma-separated list on the row and compares it with the enabled set.
* **Declined — `docker compose config` as the reader.** The reviewer's own table
  (opportunity 11) calls this "NOT WORTH IT" for this wave, and the ADR records G2
  as deliberately open. I agree: it would make `--list` require the Docker CLI, and
  the report on a host with no Docker is one of the reasons `--list` is a gate. The
  price is that the subset must be maintained by hand — which is what the refusal
  set and the corpus are for.
* **Declined — a YAML engine in the script.** Same reason, and the project has no
  PyYAML dependency by choice.
* **Declined — the reviewer's cheaper R-W1-105 fix (refuse the empty profile list).**
  It would have refused a file Compose accepts, and it would not have given the
  `COMPOSE_PROFILES` behaviour at all. The deviation is recorded in the ADR.

## 6. Residual risks and anything the delta reviewer should check

1. **The mandatory independent-review subagent could NOT be run.** Every attempt to
   spawn a reviewer (`code-reviewer`, `general`) failed with *"Subagent depth limit
   reached (1)"*. The standing orders say to stop and report the blocker rather than
   pretend the workflow was completed — so I report it here, and I did the review
   **myself**, with evidence: the reversal measurement (§3), the 24-shape comparison
   against real Compose (§0, §2.2), and the reasoning in §2. **The delta reviewer
   should read this change as unreviewed-by-a-second-pair-of-eyes.** The change is
   also larger than the findings strictly require (the reader was restructured, not
   patched), which raises the value of that review.
2. **The reader now refuses more than it used to.** A compose file that Compose
   accepts and that the reader used to accept (silently, wrongly) is now refused:
   a flow-mapped service, a flow-mapped `services:` map, a service at another
   indent. That is the intended trade, but an operator with such a file will now get
   a refusal where they used to get a wrong plan. The message names the file and the
   shape, so the fix is obvious.
3. **The profile list is read by a hand-rolled parser.** The two spellings Compose
   uses are covered; a third spelling would be mis-read. The consequence is bounded:
   a profile name that is mis-read is a service reported as *not fetched* when it
   should have been fetched — reported, not silent. The pin rule still covers it.
4. **`COMPOSE_PROFILES` is a new environment variable** the script reads. It is
   Compose's own, and the tests scrub it. An operator who has it set in their shell
   gets the profile's images fetched — which is the point.
5. **The `--list` output format changed**: a gated service is now a `skip` row with
   a trailing `[…]` bracket, and the row *parser* in the test accepts it. A CI job
   that parses the `--list` output with its own regex would need the same change.
   The three columns (action, image, service) are unchanged.
6. **The final success message changed** when something was skipped: "every image
   this stack runs is present" plus the count and the names, instead of "every image
   the compose file(s) name is present". The old sentence is still used when nothing
   was skipped.
7. **`mypy src` and `ruff src tests` are unchanged** (0 and clean) — no `src/` file
   was touched, no `# noqa`, no `type: ignore`, no `pyproject.toml` change, no new
   dependency.

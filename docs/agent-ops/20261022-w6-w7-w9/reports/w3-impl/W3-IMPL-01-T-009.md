## 2. Why `python-is-python3` is there (VERIFIED rationale)

`src/paa/sandbox/base.py::build_child_env` builds the sandboxed plan-step environment with `PATH=/usr/local/bin:/usr/bin:/bin` — deliberately not the host PATH, because the host PATH leaks the developer's toolchain and can put an attacker-writable directory ahead of system ones (`AGENTS.md`: "The host fix was one line… widening the sandbox's PATH would have undone the security property"). `src/paa/agents/reasoning.py::WorkerCell` runs plan steps with `python -c …` by default. `actions/setup-python`'s tool-cache interpreter and the runner's `python3` are not on `/usr/local/bin:/usr/bin:/bin`, and there is no `/usr/bin/python` under the name `python`. So a plan step exits 127, the worker fails, the task never reaches `MUTATION_COMMITTED`, and six assertions that expect `COMMITTED` fail for a reason unrelated to the code (`AGENTS.md`: "six assertions fail on the runner"). `python-is-python3` installs `/usr/bin/python`, which the sandbox's minimal PATH finds. Verified locally: `/usr/bin/python` exists on this host; the sandbox's PATH property is in `src/paa/sandbox/base.py` (read-only, not re-checked line by line here — see `AGENTS.md` account).

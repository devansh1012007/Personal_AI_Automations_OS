## 4. The checker — `tests/conventions/test_docs_references.py`

### Scope (stated in the file itself)

**In scope:** every markdown file under `docs/`, plus `README.md` and
`AGENTS.md` at the repository root — the documentation a reader is sent
to by the repository itself.

**Excluded, with the reason stated in the file:**

* `docs/agent-ops/` — this run's own written trail. A reference in it was
  true when written and is *allowed* to have rotted; it is a record of
  what the run found, not a description of the tree, and "a
  run-scoped report is 'a directory the next run will not read'".
* `docs/plans/` — dated proposals; a plan discusses references as
  findings rather than citing them (this task's own plan quotes
  `cli/main.py:208` and `daemon.py:61` as the blank-line references it
  found).

Both exclusions are whole directories with stated reasons, not a list of
documents that happen to fail. The lock still catches a reference that
rots inside its scope.

### What it asserts

For every `path:line` (or `:NNN` continuation, or path range) reference:
the file exists and names exactly one file (a bare `base.py` names eight
files in this tree and is rejected as ambiguous); the cited line is not
past the end of the file; the cited line is not blank. Resolution is
repository-relative for paths containing a slash (also tried under
`src/paa/` for the docs' module shorthand), and unique-file-name
resolution for bare names.

### Limitations (stated in the file)

The lock cannot see a reference that is wrong without being broken — the
line exists, is not blank, and no longer holds what the sentence claims.
That half is the hand verification in §3.

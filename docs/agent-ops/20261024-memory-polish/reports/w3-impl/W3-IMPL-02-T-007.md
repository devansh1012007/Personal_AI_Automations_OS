`src/paa/context/gatherer.py`. Ranking is currently purely mechanical
(tier → relevance×confidence → importance → id). This change adds an optional

## 3. Root cause

No root-cause defect — this is additive surface. The gatherer was designed to be
pure, synchronous and deterministic; the roadmap now asks for an opt-in LLM
relevance ranking. The fix is to inject a `ranker` callable seam behind a default
of `None`, preserving the existing mechanical path byte-for-byte when absent,
rather than hard-coding a model call or making ranking mandatory.

## 4. Approach chosen and why

**Chosen:** optional constructor parameter
`ranker: Ranker | None = None` where
`Ranker = Callable[[tuple[list[ContextElement], frozenset[str], float]], list[ContextElement]]`,
stored as `self.ranker`. `_compile()` runs the unchanged mechanical sort via
`_rank_key`, then — only when `self.ranker is not None` — invokes it exactly once
with `(pool, required_slots, invariant_importance)` and reassigns `pool` to the
returned order before packing. With `None` the method returns the mechanical
result exactly as before (no call, no branch overhead beyond an `is None` check).

**Alternatives rejected:**
- Make ranking mandatory / default-on: rejected — violates the optional-default
  requirement (brief AC #2) and the "no model required" convention.
- `try/except` fallback to mechanical path when the ranker raises: rejected — an
  injected callable that raises should propagate ("fail loud"), matching the
  compaction summarizer convention W3-IMPL-01 established and the gatherer's
  "fail loud at the boundary" ethos (ceiling assertion at gatherer.py:565).
- Re-sorting after the ranker: rejected — the ranker's output order is authoritative
  for packing (brief AC #3); re-applying `_rank_key` would defeat the injection.

This addresses the cause (no LLM seam exists) not a symptom, and is fully
additive/backward compatible.

## 8. Long-run test

- **Source:** behavior derived from brief ACs and Plan1 C07/C12; verified against actual `gatherer.py` source (read, not assumed).
- **Load (100x/concurrency/partial failure):** `_compile` is pure, synchronous, stateless after construction (no `self` mutation between calls — `self.ranker` is read-only). One ranker invocation per compile; no locks, no I/O, no shared mutable state. No concurrency surface to exhaust.
- **Hostile input:** empty pool (ranked once with `[]`), ranker returning a subset, ranker returning a different order, ranker raising (propagates), ranker returning more elements than fit (ceiling still enforced). Mechanical floors (`confidence_floor`/`relevance_floor`) still apply pre-rank.
- **Operability:** additive, default-off; observable via the constructor param and the ranker's call count; rollback = remove the param (restores mechanical-only exactly). No data migration (no persistent state added).
- **Reversal:** reverting the `_compile` hook makes the injected-path tests fail (ranker never called), proving the tests test the fix. Mechanical-default tests continue to pass.

## 9. Edge cases and abuse scenarios

Handled: empty pool (ranked once, empty packet); ranker returns subset (vacant slots recorded correctly); ranker returns different order (packing follows ranker); ranker raises (propagates, no try/except); ceiling enforced post-rank (DoD bound); `compile_worker_packet` also routes through `_compile` (narrative filter still applies pre-rank). Consciously not handled: ranker returning non-`ContextElement` objects (type error at packing boundary — caller's contract, `Ranker` type enforces); ranker mutating the pool (caller's contract). Unknown: none within scope.

## 10. Performance and security considerations

No secrets logged (structlog `log` unused for the ranker path; no key material). No new dependencies; `Callable` from the standard library. Mechanical ranking remains the default, so hosts without a model are unaffected (Plan1 §D4).

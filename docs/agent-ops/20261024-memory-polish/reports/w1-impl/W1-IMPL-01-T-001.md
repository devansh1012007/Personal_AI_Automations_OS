## 3. Root cause

The memory subsystem (`FactRepository`, `MemoryCreator`, `WorldModel`) is fully built and tested internally but has no CLI surface. `src/paa/cli/main.py` registers every other verb as a top-level command and `register_agent` for `agent`, but nothing registers a `memory` group. Operator cannot list/search/drain memory or read world-model docs from the terminal. No tests exist for CLI memory (tests/cli/ has only test_cli.py).

## 4. Approach chosen and why

Add `memory_app = typer.Typer(name="memory")` in `src/paa/cli/main.py`, define five subcommands on it, and register via `app.add_typer(memory_app, name="memory")` next to `register_agent(app)`. Each subcommand builds a `Runtime` via `_build_runtime()`, performs its read/drain in an inner `async def _do()`, and closes in `try/finally rt.close()`, mirroring cli/main.py:81-98 and the `register_agent` pattern in cli/coder.py:56.

Each command constructs the memory objects it needs from the runtime (read-only use, no modification):
- `facts <entity>`: `FactRepository(rt.db).resolve_entity(entity)` then `query_facts(entity_id=...)`, render a rich Table; empty -> "[dim]no facts[/dim]".
- `search <text>`: `FactRepository(rt.db).search_facts_by_text(text)`, render Table; empty -> "[dim]no matches[/dim]"; NUL/ValueError -> clean refusal exit 1.
- `signals [--status ...]`: query `cold_lake_signals` via `rt.db.fetch_all`, optional IN filter (bound params), Table of id/channel/status/timestamps.
- `drain`: `MemoryCreator(rt.db).run_batch(limit=25)`, print the seven BatchReport counters in a Table.
- `world-model <doc>`: `WorldModel(rt.settings.storage.vault_path).read_managed(BeliefDocument(doc))`, print text or "[dim]no managed section[/dim]"; unknown doc -> clean refusal exit 1.

Alternatives rejected:
- Top-level `@app.command()` per verb (facts, search, ...) — rejected; brief and Plan C01 require a `memory` group with `app.add_typer(memory_app, name="memory")`.
- Printing raw JSON/dict — rejected; existing CLI convention (ledger/status/doctor) uses rich `Table` via `console.print`, so `Table` matches house style and `--help`/output is operator-friendly.
- A new module `cli/memory.py` — rejected; brief's WRITE-SET is `cli/main.py` only, and the `register_agent` pattern puts command definitions inline in coder.py registered at main.py bottom, so keeping memory commands in main.py is consistent and keeps the write-set minimal.

No new dependencies; no schema change; no modification of read-only memory modules (only imports).

## 9. Edge cases and abuse scenarios

Handled:
- Empty DB/vault -> graceful "no facts"/"no matches"/"no signals"/"no managed section"/zero counters, exit 0.
- Unknown entity name -> "no facts" (graceful, exit 0).
- NUL byte in search text -> clean refusal, exit 1 (ValueError from search_facts_by_text caught).
- Unknown belief doc -> clean refusal, exit 1.
- Repeated `--status` values -> bound `IN (...)` placeholders, no SQL injection.
- Drain on empty backlog -> zeros, exit 0.

Consciously not handled:
- `search` on a PostgreSQL backend — the CLI is backend-agnostic via `rt.db`; `search_facts_by_text` already handles both dialects (like.py). Not tested against Postgres here (requires server, out of scoped checks).

Unknown: none identified.

## 10. Performance and security considerations

- No secrets logged; no API keys touched by this CLI surface.
- `signals` query binds all user values (`?` placeholders); the dynamic `IN` list is built from `?` repetition only, so no interpolated user text reaches SQL (S608-safe; `# noqa: S608` on the static f-string SQL, matching facts.py convention).
- `world-model` reads only files under `settings.storage.vault_path` via `WorldModel.path_for(doc)` where `doc` is a `BeliefDocument` enum value — no path traversal (enum values are fixed filenames, no `..` possible).
- `drain` reuses the existing one-transaction-per-signal, per-signal isolation of `run_batch`; a poison signal cannot abort the batch (existing creator.py behavior).

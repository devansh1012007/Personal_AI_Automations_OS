# Implementation report — W2-IMPL-03 — T-003 LLMFactExtractor

## 1. Task and acceptance criteria (restated)

Implement `LLMFactExtractor` in `src/paa/memory/creator.py` implementing the `FactExtractor` protocol (async `extract(envelope) -> list[CandidateFact]`), calling `model.complete_structured(prompt, schema)` with a JSON schema returning `{"facts": [{"subject", "predicate", "object"}]}`, parsing into `CandidateFact` objects, applying containment checks on the raw payload, using confidence 0.70 (below rule-based), returning empty list for no facts, and raising `MalformedSignalError` on model failure. Scoped gate: `pytest tests/memory/test_llm_extractor.py -q`, `ruff check src/paa/memory tests/memory`, `mypy src/paa/memory` all green.

## 2. Verification that the problem exists

`creator.py:238-254` declares the `FactExtractor` protocol; `creator.py:354-618` implements only `RuleBasedExtractor`; `runtime.py:447-451` already attempts `getattr(_creator_mod, "LLMFactExtractor", None)` and degrades to rule-based when absent (T-005 done in Wave 2a, committed at a8aad78f). `tests/memory/test_llm_extractor.py` (7 tests) passes using `ScriptedLLMExtractor` injected via `MemoryCreator(extractor=)`, but no `LLMFactExtractor` class exists, so `PAA_MEMORY__EXTRACTION_MODEL` can never take the LLM path — the failure is "no LLM-backed extraction path exists" per the brief. `[VERIFIED src/paa/memory/creator.py:354-618, src/paa/runtime.py:429-454]`

## 3. Root cause

The `FactExtractor` seam exists precisely for an LLM substitute (creator.py docstring, lines 14-17), but the seam is never filled. `Runtime._build_memory_creator` defensively degrades when `LLMFactExtractor` is missing, so config `extraction_model` silently falls back to rule-based extraction. Root cause: missing class implementation, not a wiring or config defect.

## 4. Approach chosen and why

Add `LLMFactExtractor` co-located in `creator.py` right after `RuleBasedExtractor` (Plan1 D2: same file, the protocol lives there). It calls `_reject_suspicious(envelope.raw)` first (C0 incl. NUL, ANSI, managed-block markers — same helper as RuleBasedExtractor), then `model.complete_structured(prompt, _FACT_TRIPLE_SCHEMA)` with the triple schema, wraps any model exception in `MalformedSignalError`, parses defensively (missing/non-list `facts` → `[]`; bad triples skipped; missing subject/predicate/object skipped; object via `_scalar_to_text` which enforces `MAX_VALUE_CHARS`), caps at `MAX_CANDIDATES`, and sets confidence `0.70` (< `_CONFIDENCE_TRIPLE` 0.95). No new file, no protocol change, no config/runtime touch — purely additive, rule-based default untouched.

Alternatives rejected: new module `memory/llm_extractor.py` (unnecessary module boundary for one class, Plan1 D2); validating triples strictly like the scripted test extractor (brief gotcha §53 says skip bad triples gracefully for the real LLM path); confidence equal to rule-based (would erase the reliability distinction the confidence field exists to encode, creator.py:342-351).

## 4. Findings
### R-W2-D-01 [MINOR] First-tick construction-failure fallback bypasses dry-run preview
- Location: `src/paa/daemon.py:256-259` (`await DecaySweeper(self._rt.db).sweep()` with no `dry_run` arg) vs flag `src/paa/daemon.py:244`.
- Evidence: on first tick (`_curate_preview_done=False`, `dry_run=True`), a curator construction failure (import or wiring) falls back to bare `sweep()` which deletes (and archives) immediately. IMPR-01 §6 discloses this ("pre-existing behavior") and §1/DECISION still states the preview "deletes nothing on first tick" — true only for the happy path.
- Why it matters: R-W2-002's guarantee is operator-facing (preview volumes before any delete). The failure branch deletes exactly the phase (DECAY) most likely to be large, on the one tick where the promise was made. Narrow trigger (broken wiring), but it is a direct hole in a MAJOR fix, currently unpinned by any test.
- Recommended fix (root-cause, one line): `await DecaySweeper(self._rt.db).sweep(dry_run=dry_run)` in the fallback, plus a test: fake curator module + first tick → stale fact remains, preview log emitted; second tick deletes. `sweep(dry_run=)` already exists (`decay.py:150`).

### R-W2-D-02 [MINOR] Preview flag consumed by a partial/errored preview pass
- Location: `src/paa/daemon.py:270-271` (`self._curate_preview_done = True` after any successful `run_maintenance` return) and `src/paa/memory/curator.py:197-210` (budget `stopped_early_at` / per-phase `errors` still return a report).
- Evidence: a first tick that stops early (budget) or errors in early phases still consumes the preview. Concrete case: zero-budget tick → `stopped_early_at=DECAY`, no phase ran, flag set; next tick deletes phases that were never previewed. The existing zero-budget test masks this by manually setting `daemon._curate_preview_done = True` (maintenance_loop.py:446) before the second tick.
- Why it matters: same operator promise as R-W2-D-01; in production the 7200s budget makes a partial preview unlikely, but any budget clamp/error resurrects an unpreviewed delete. The safe direction (restart re-previews) is already chosen; this makes the in-memory flag match it.
- Recommended fix (root-cause): only set `self._curate_preview_done = True` when `report.completed_fully and report.errors == 0` (or track preview per-phase); add a test driving the real flag through a zero-budget first tick instead of hand-setting it.

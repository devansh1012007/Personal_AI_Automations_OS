## 3. Root cause

Deterministic extraction filters return `None`/`continue` with no observability channel: the contract (`list[CandidateFact]`) literally cannot report what it discarded. First-person loss has two faces: bare `I`/`we` subjects are dropped as pronouns, and auxiliaries (“I am …”) are absorbed into the subject (`"I am"`), creating a junk entity that resolves against nothing later. Both produce the same symptom — the agent “forgot” what it was told — with no counters to triage.

## 4. Approach chosen and why (alternatives rejected)

- **Counters live on the result, probed from the extractor — protocol unchanged (chosen).** New `ExtractionDropCounts` dataclass (8 fields + `total` + `as_dict()`). Both built-in extractors keep per-signal counters reset at the head of `extract()` and expose a copy via a `drop_counts` property; `process_signal` snapshots with `getattr(extractor, "drop_counts", None)` — extractors without the attribute (any pre-C05/third-party implementation) yield zero counts. Rejected: (A) changing `extract()` to return `(candidates, counts)` — breaks the protocol and every test double; (B) log-only counters in the extractor — `ProcessingResult` stays empty, failing T06's public-result assertion; (C) a required protocol method — `isinstance`/`mypy` break on `ScriptedLLMExtractor` and the integration `ScriptedModel`.
- **`non_storable` is counted in `process_signal`, not the extractor (no double-count).** The extractor counts only pre-candidate drops; `_is_storable` discards are post-return, so they cannot overlap. Pinned by `test_non_storable_candidate_is_counted_by_creator_not_extractor` (extractor-side fields 0, `non_storable == 1`).
- **First-person mapping = first-word, case-folded, all rule paths (chosen).** `_first_person_mapping(name)`: first whitespace token, lower-cased, in `{"i","we"}` → `("user", 0.3)`. Required because the regex absorbs auxiliaries (`"I am based in Berlin"` has subject `"I am"`). Applied in `_from_sentence`, `_from_triples`, `_walk`, and key-value (the four `CandidateFact` sites with a subject). Rejected: exact-match only (maps ~none of the natural corpus — empirically proven above); sentence-path only (leaves triple/structured `{"subject":"I"}` creating entity `I`, an inconsistency INV-03 flagged as underspecified — mapping everywhere is the smaller invariant); LLM extractor mapping (out of “do not re-architecture LLM path” scope; recorded as out-of-scope finding 2).
- Attribution: question branch before hedge branch (one dropped line increments exactly one field); empty sentence-split chunks and schema-reserved keys are never counted (they are not drops).
- Log: one batched `memory.extraction_dropped` debug line per signal with non-zero drops (never one line per dropped line — the 10k-line hedge-spam shape), plus `dropped`/`drop_counts` on the batch-completion info line. `memory.signal_ignored`/`signal_processed` lines unchanged.
- Confidence for user facts stays `_CONFIDENCE_SENTENCE` (0.60), pinned by test (INV-03 left this “undecided”).
